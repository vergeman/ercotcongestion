Is L3837 Radial?

A near-radial network is one that's mostly radial (tree-structured, power flows
one direction from source to load) but has a few tie lines or loops added.

Pure radial = no redundancy, single path from source to each load. Near-radial =
almost that, but with occasional loops that create a small number of alternate
paths.

When `h_diag` is close to 1.0 (meaning the line is radial — tripping it
disconnects part of the grid), the LODF values blow up. You marked those as
np.nan, but my contingency_stress code treats them as 0.0 v

If L3837 is a radial or near-radial line, and PyPSA's BODF computation didn't
sanitize it. That's why its "outage" produces impossibly many overloads — the
LODFs are amplifying a 104 MW base flow into massive shifts everywhere.

In a healthy network, LODFs are bounded: |LODF| ≤ 1 for most pairs, with values
close to 1 only for very tightly coupled parallel lines. If you're seeing LODFs
of 10 or 100, the contingency is mathematically blowing up

LODF values of 32, 16, 12, 8 are physically impossible for properly-handled
contingencies. These extreme integer-looking values (8, 16, 32, 128 — all powers
of 2) suggest near-singular linear algebra.

L3837 is in a part of the grid where there are very few alternate paths.
Tripping it doesn't quite disconnect the grid (so the LP didn't flag it as
infeasible), but the alternative paths are so weak that flows blow up by 32× or
128× to compensate. In real-world terms: this line is a
single-contingency-no-margin corridor — operators would never let real flows
reach a level where its loss is acceptable.

Texas2k case is a planning model. It captures realistic topology and load
patterns, but it's not built to perfectly satisfy N-1 security like a real
operating model. Some buses end up connected via single weak paths because the
model-builders cared about geographic realism, not contingency security.

Real ERCOT enforces N-1 security as a hard constraint in SCED — they wouldn't
dispatch a flow pattern where any single line trip causes overloads. Your
synthetic grid doesn't have that constraint baked in, so it produces more
dramatic cascade scenarios.

For validation against real basis, this matters: synthetic-network N-1 events
may be more dramatic than real ERCOT N-1 events. `modeled_congestion` should
still correlate with basis on average, but extreme values may need calibration.
